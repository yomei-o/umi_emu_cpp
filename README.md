## なぜ CPU で足りるのか — MLS-MPM

本家が SPH をやめて MLS-MPM に替えた理由がそのまま効きます。**近傍探索が要らない。**

| | 1粒子あたりの仕事 |
|---|---|
| SPH | 半径内の近傍を探す（探索そのものが高い） |
| **MLS-MPM** | **3×3×3 の格子を触るだけ。固定。分岐なし** |

```
P2G   粒子の質量と運動量を、二次Bスプラインの重みで格子へ撒く
      アフィン項 C（APIC）と応力を一緒に運ぶ ← MLS-MPM の要点
格子   v /= m、重力を足し、壁で速度を止める
G2P   格子から速度を集め直し、同時に速度勾配 C を復元する
      体積比 J *= 1 + dt·tr(C)   ← 圧縮の記録
```

水（弱圧縮性流体）は応力が圧力だけなので

```
stress = -dt · V · 4/dx² · E · (J - 1)
```

のスカラーで済みます。せん断を持たないぶん固体より安い。

**dt は勝手に決められません。** 弾性波の速さ c = √(E/ρ) に対して dt < dx/c を満たさないと必ず飛びます
（最初これで J が NaN になりました）。E を変えたら dt を引き直しています。

## 描画 — 画面空間の流体レンダリング

粒子を一個ずつ球として描くのではなく、**深度をならしてから法線を作る**のがこの手法の肝です。

1. **深度** 粒子を球のインポスタとして撒き、いちばん手前の視空間深度だけ残す
2. **平滑化** ただの Gauss だとシルエットが溶けるので、中心深度から一定の窓に**切り詰めてから**混ぜる
   （narrow-range filter）。双方向フィルタより輪郭の癖が少ない
3. **法線** ならした深度から視空間の位置を復元し、差分の外積で法線を作る
4. **厚み** 深度テスト無しで足した弦の和。**粒子の重なりぶん過大になる**ので、
   1粒子が担う体積と球の体積の比を掛けて**実際の光路長 [m]** に直す（これを忘れて水が真っ黒になった）
5. **着色** フレネル（Schlick）で反射と屈折を混ぜ、厚みぶん Beer-Lambert で吸わせる

**水の青は色を塗っていません。** 赤から先に吸われた結果です（吸収係数 6.2 / 2.3 / 0.7 [1/m]）。

## CPU で間に合わせるためにやったこと

素直に書くと 145 ms/frame でした。内訳を測って、効く順に潰しました。

| 手 | 効果 |
|---|---|
| 流体だけ**半解像度**で描いて最後に拡大 | 深度・平滑化・着色が 1/4 |
| **内部の粒子を描かない**（質量格子で6近傍が詰まっていたら捨てる） | 塗る画素が半減。球の面積が効くのでこれが一番大きい |
| 背景を**全解像度で焼いて使い回す**＋水のある矩形だけ処理 | 着色 9.6 → 1.6 ms |
| expf / powf を**表引き**に | 毎画素5回呼ぶと、そこだけで 50ms 超える |
| 粒子を**セル順に並べ替え**（計数ソート） | 長時間回したときのキャッシュ対策 |

結果 **145 → 25 ms/frame**（43,500粒子、ネイティブ -O3）。

深度パスは 93.9 → 5.2 ms（18倍）。**推測せずに毎段の時間を測ったのが効きました。**

| | webgpu-ocean | これ |

## ビルド

```bash
./build.sh umi_os        # → wasmdist/umi_os/{sim.js,sim.wasm}
```

ネイティブ自己テスト（PNG を書き出し、毎段の所要時間も出す）:

```bash
clang++ -O3 -std=c++17 -I. -o umi_test src/umi_os.cpp
./umi_test 260 umi.png
```
